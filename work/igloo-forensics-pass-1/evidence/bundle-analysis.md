# Igloo public bundle forensic notes — pass 1

Scope: read the two public, downloaded production bundles `index-2eb69c09.js` and `App3D-f554a111.js`. No application code was changed. These notes report published client implementation, not private systems. Runtime frame captures and observed interaction outcomes remain separate evidence. **Confirmed** below means verified in the published source, not necessarily exercised in this browser session.

Evidence companion: `bundle-snippets.json`. IDs B01–B50 contain verbatim source and exact zero-based **UTF-16 string code-unit** offsets (JavaScript `String.indexOf`), not UTF-8 byte offsets. Both bundles are minified, mostly one line. Do not use offset as a line number. Minified identifiers are specific to these bundle versions.

## Stack and initiation

- **Confirmed:** Three.js revision **165** (`const Aa="165"`, B03 offset 284), GSAP **3.12.5** (B05, 767900), and pmndrs **postprocessing 6.35.5**, dated June 1, 2024 in its vendored header (B04, 577293). These are library versions embedded in the downloaded site, not claims about present package releases.
- **Confirmed:** The entry bundle contains Svelte's compiled component lifecycle/runtime, including `$$.fragment`, `$destroy`, `$on`, `on_mount`, Svelte CSS keyframe names; App3D imports that runtime. Svelte orchestrates loader, app root, router and WebGL fallback. The exact Svelte release is not established.
- **Strongly inferred:** Vite build tooling from the modulepreload polyfill, dynamic import helper, hashed asset names and emitted `vite:preloadError` event. These signatures do not establish a particular Vite version.
- **Confirmed:** Entry dynamically imports App3D; loader is shown before import, App3D `.ready` is awaited, and loader then fades out. ASCII glyph strip has a five-second looping CSS content animation; loader glyph outro takes 250 ms, overlay 750 ms with cubic easing. B02 offset 15819 plus the entry's loader component earlier in file.
- **Confirmed:** GSAP registers custom ease plugins `Ei`, `dg`, `fg` and app defaults (`force3D:true`, `ease:"power2.inOut"`, `duration:.6`, `overwrite:"auto"`). `re.ticker` is the active frame clock, emitting `webgl_prerender`, `webgl_render`, `webgl_postrender` and calculating average FPS. B06, 842781.
- **Confirmed distinction:** `ScrollTrigger` occurs **twice**, both inside the bundled GSAP core's optional integration bridge. There is no bundled ScrollTrigger implementation, registration, app `scrollTrigger` configuration, or active ScrollTrigger call found. The site implements its own scroll controller. Do not label it a ScrollTrigger website on token presence alone.
- **Confirmed:** startup requires WebGL2 and renders a DOM error message otherwise. Initial DPR cap is `min(devicePixelRatio,1.15)` when device DPR ≤2, otherwise `min(devicePixelRatio,1.5)`. Adaptive DPR, audio context and shadow-map options are enabled. Custom `entry_ease`, `entry_ease_2`, `entry_ease_3`, `igloo_ease_1` and `inOut5` Bezier curves are initialized. B23, 1484464.

## Actual scene and render organization

- **Confirmed:** `ty={igloo:F3,cubes:aF,entry:UF}`; root `jF` constructs one offscreen composer for each, plus separate `JF` detail scene/composer and an orthographic `GF` UI scene/pass. `createScenes()` waits on **all** five scenes' `.uploaded` promises before declaring ready. B22, 1474794; scene definitions B16/B18/B19/B20/B21.
- **Confirmed:** A fullscreen triangle called `Main triangle mesh` uses `f3` compositing material; initial load uses `p3` material. Primary visible content is shader-composited scene render textures, not stacked DOM sections. Geometry uses the oversized triangle `[-1,-1,0,3,-1,0,-1,3,0]`. B22 and B15.
- **Confirmed:** UI pass clears neither scene color nor screen by default (`uiPass.clear=false`) and is added to the main compositor. Gamma/SMAA passes are sorted last by `tA.addPass`; global bloom is added once by scenes using `__hasBloomPass`. Broad flow: active scene offscreen render(s) and scene correction → fullscreen transition/detail composite → orthographic UI overlay → bloom and high-quality SMAA/output encode. Exact runtime pass order and framebuffer attachment formats require capture. B11/B10/B37/B22.
- **Confirmed:** Wrapper constructs renderer with `{alpha:false,antialias:false,stencil:false,depth:false}`, but Three renderer itself requests WebGL context **alpha:true unconditionally**, at offset424014, while retaining false for its internal background flag. This explains observed browser context attributes alpha:true; do not confuse wrapper options with actual context attributes. Main renderer AA is off; app explicitly adds SMAA instead. Offscreen scene render targets may have their own depth buffers; renderer constructor `depth:false` is not evidence that every pass lacks depth. Renderer tests floating point render target support and records float linear filtering extension. B07,874465; B47,422729.
- **Confirmed:** Canvas is appended inside a **closed shadow root** on an otherwise ordinary div: `t.attachShadow({mode:"closed"}).append(this.renderer.domElement)`. Normal `document.querySelector('canvas')` or visible DOM audit can miss it. B11, 1030473.
- **Confirmed:** Global shared uniforms / UBO convey time, delta ratio, resolution and UI resolution to custom materials. Main engine resizes rendering to pixel resolution times current DPR while CSS canvas dimensions remain viewport pixel dimensions. B11.
- **Confirmed:** `Jo._upload()` traverses meshes, gathers texture load promises, temporarily disables culling and makes material/mesh visible; `compileAsync(scene,camera)` and `initTexture(texture)` run before a dummy RT render. Original visibility is restored and `.uploaded` resolves. This is deliberate shader/texture warm-up, a concrete polish technique, but runtime hitch avoidance must still be measured. B08, 880961.

## Scroll controller and transitions

- **Confirmed:** Native page scrolling is disabled by entry CSS (`html/body overflow:hidden`, `touch-action:none`; B01, 1708). Scroll input is event-driven from wheel, ArrowUp/ArrowDown and drag; no conventional long document progress drives the scene.
- **Confirmed:** Root scroll state has `targetY2` (raw target), `targetY1` and displayed `y`. Wheel adds delta×**0.00075**. Arrow keys add ±150×0.00075. Touch drag adds normalized `delta11.y×1.25`. Any input stops auto-centering and kills the GSAP scroll tween. B22.
- **Confirmed:** Frame smoothing uses FPS-aware `lerpFPSLimited(targetY1,targetY2,.075,100*scrollMultiplier)`, then `lerpFPS(y,targetY1,.15)`; target is clamped to displayed y±750×scrollMultiplier. Velocity accumulates absolute movement, decays by FPS friction .98 and clamps to [0,1]. This yields momentum with bounded lag rather than browser inertial scroll alone. B22.
- **Confirmed:** Scene heights are **2.35** (igloo), **3** (three cubes in current configuration), **5.5** (entry), yielding **10.85 logical scroll units**. `y % total` wraps, including negative y correction. View occupies one logical unit. A scene progress is `(view bottom - scene top)/(scene height + 1)`. The root determines two overlapping scenes, renders those visible composers, and drives global `uProgress` for the seam. This is an infinite/cyclic experience in source. B22/B16/B18/B19.
- **Confirmed:** after **1.4 seconds** without target change, controller finds the closest boundary and snaps/auto-centers. General boundary tween starts at 2 seconds; cube scene centers nearest object in **1.6–2.4 sec**; entry centers its final progress after `.15`, with **2–20 sec** duration based on remaining distance. Source defines initial/final auto-center progress .495/.495 for igloo and .2/.76 for entry. B22/B18/B19.
- **Confirmed:** main shader's interscene effect is a **textured diagonal cut**, not a simple CSS slide. RGB channels of `scroll-datatexture.ktx2` feed ice cut (red), technical displacement (green), slope displacement (blue). It uses aspect-corrected UVs, parallax 0.4, displacement .025 and five-iteration chromatic aberration, with blue-noise modulation hiding seams. Shader branches avoid reads of a fully hidden scene. B15, 1091502.
- **Confirmed caution:** source retains a commented-out velocity-reactive cut. Active diagonal slope is fixed `-0.2*aspect`, so do **not** claim active slope tracks velocity from that commented block. `uProgressVel` is updated by root but not used in the active global transition fragment shader.
- **Confirmed:** home route `/` and detail `/portfolio/:project`. Routes are blocked during transition choreography; returning home re-enables scroll after one second. Project detail opens only for a valid cube hash and the cube scene's visibility, except first navigation supports direct URL loading. B22/B23.
- **Confirmed:** detail entry uses two uniform envelopes: `uDetailProgress`→1 over **1.25 s power3.in**; `uDetailProgress2`→1 over **1.25 s sine.out** delayed another **.75 s**. Shader mixes cube/detail with frost distortion, technical displacement and chromatic aberration; blend starts at uDetailProgress .4. Close resets first over 1.25 s and second .6 s. B22/B15.

## Camera and animation choreography

- **Confirmed:** Multiple paused GSAP timelines are **scrubbed via `.progress(scene.progress)`**. Timeline durations describe their internal phase mapping; for scroll-scrubbed timelines they are not wall-clock durations of a user's scroll. Auto-playing intro and detail transition durations *are* clock durations. B17/B19/B22.
- **Confirmed:** igloo camera initially configured fov30, position(-14,4,14), target(0,1,0); pointer displacement(.07,.025), shake .01 and speed .5. Intro starts camera high at (-14,21,14), then interpolates intro and timeline cameras using `introWeight`. Scroll timeline animates y from +9/+14 down over14 units of timeline time and shifts x/z over14 starting at7. Portrait zoom = min(1,aspect×1.25). B16/B17.
- **Confirmed:** Intro outline materialization 0→1 at t0 for2.5 s; cage reveal4 s at0, cage fade starts2.1 for3 s and then hidden; solid igloo materializes starting1.1 for2.25 s; terrain/mountains reveal spans .7→8.2 s; UI intro event t4.5; camera intro weight t2→7.5; scene `playInAnimation()` awaits5 s although timeline tails continue. Layered, overlapping envelopes produce staging instead of uniform reveal. B17, 1195644.
- **Confirmed:** cube camera y and target y translate with `(cube count+1)*-5.75*progress`. Its fov is **45−5×abs(scroll velocity)**, an active velocity-dependent lens effect. Cube/detail transition zooms base camera z by −3.5 over1.25+delay sec while dampening extra rotation/pointer movement. B18, 1304184.
- **Confirmed:** entry camera timeline moves from above toward y−9.83, changes target, rotates its up vector through π, then blends back toward conventional up, travels in z, and fov22→30. Pulse points at internal t2,2.95,3.8 drive `uRingProximity`, aligning post distortion with portal crossings. Visibility windows hide rings/plasma/trails/tunnel after relevant progress. Portrait zoom = min(1,aspect×1.5). B19, 1400874.
- **Confirmed:** detail camera z4→2.5 over2 s after .5 s delay; UI var fade .7 s and project text display event; selected object remains visible and gains small multi-axis sinusoidal rotation. Detail exit camera to z4 .6 s. B21, 1472532.

## Objects, shaders and simulation

- **Confirmed:** igloo model is loaded via `zt.batched("igloo.drc")`. Pieces use Three BatchedMesh (`cI`) with matrix texture and per-piece options data texture. Pointer-plane proximity and time-based functions feed spring-like displacement/bounce; two-stage FPS lerps smooth each; scroll increases radial displacement/rotation. Each piece matrix is updated with `setMatrixAt`, and shader looks up per-piece matrix/options using `batchId`. This is actual fragmented geometry, not a prerecorded image sequence. B24, 1173719.
- **Confirmed:** cube geometry builds a `boundsTree=new bg(geometry)` and uses patched BVH raycast (`bE.prototype.raycast=...` near1295621). Frost interaction raycaster uses `firstHitOnly=true`. This supports identifying **three-mesh-bvh-style accelerated raycasting**; exact package version is unestablished. B26/B27.
- **Confirmed:** ice cube uses a custom material subclass of Three MeshPhysicalMaterial (`WL extends Ys`), replacing transmission shader chunks with mipped bicubic refraction sampling, roughness/normal/env maps, blue noise, chromatic aberration and mouse frost. App constructs `new WL(3)`, so **three custom transmission samples** for these cubes, not constructor default5. Active properties include roughness.65, ior1.18, reflectivity.3; custom uTransmission1 while native transmission is set0. B25/B26.
- **Confirmed:** cube scene explicitly renders an auxiliary mipmapped transmission RT with back-facing shells and inner objects, hides text/other overlays, then swaps to front-facing shells using that texture and restores UI/plexus. Environment uses `cubes_env.exr` and PMREM generation. B18/B26.
- **Confirmed:** mouse frost runs a **512×512 ping-pong RT**. Ray-hit `uv1` becomes a splat coordinate, with movement velocity filtered over time. Texture stores trails/frost history; click navigates to matching project. Updates are gated to ≥.015 s. Sound follows motion. B27, 1282578; B41, 1279799.
- **Confirmed:** closing entry volume contains **150,000 GPU particles**. Initial positions are data textures. Ping-pong compute material maintains position and velocity, reads a `sampler3D tVolume`: RGB decode surface gradient, alpha decodes signed distance; curl/bitangent noise, attraction to original positions/surface, and fluid velocity push shape movement. Volume names correspond to current social link: peachesbody_64, x_64, medium_32. B28, 1355503.
- **Confirmed:** source has active fluid simulation (128 simulation/dye res, pressureIterations2, curlStrength0) influencing those particles through screen-space velocity texture. The shader maps camera-space right/up velocity onto world displacement. This is not proof it uses an external fluid library; implementation is bundled and custom. B28 and fluid source around1054400.
- **Confirmed:** reusable `gE`/`r3` particle mechanism uses 2 render targets and MRT outputs to compute particles on GPU. Intro snow uses1,200 instanced quads; intro numeric points sample a32-row spritesheet with spatial shockwave timing. Detail scene has250 larger particles and10,000 small points responsive to shared mouse simulation. B42/B43/B21 plus particle helper near1072301.
- **Confirmed:** igloo and cube scenes apply3D LUTs `igloo/igloo_scene.ktx2` and `cubes/cube_scene.ktx2` with **tetrahedral interpolation**. Igloo also modulates a diagonal brightness gradient. Film-grain/RGB-shift blocks present there are **commented out**; do not report them as active. B39/B40.
- **Confirmed:** entry post shader actively uses angular/noise distortion near portals, square texture displacement, small HSV boosts and a blue-noise diagonal glare. B29, 1397661.
- **Confirmed distinction:** Fd includes generic addGodRays, addDOF, Gaussian blur, Kawase blur and selective bloom methods, but textual search finds **no application calls** to those methods. Do not claim runtime depth of field, post god rays or those blur passes solely because vendored/helper code exists. Active addSMAA and addBloom call sites were verified. Similar caution applies to generic glTF/video/SVG loaders; they are capabilities, not evidence of loaded resources.

## UI, interactions and responsive structure

- **Confirmed:** orthographic UI scene holds logo, scroll instruction, sound toggles, close button and projects. Text is `Ui extends Mesh` named `Text (MSDF)`, using font JSON geometry worker and `IBMPlexMono-Medium-datatexture.ktx2`. Primary content text is therefore WebGL MSDF meshes, despite regular/medium WOFF/WOFF2 fonts also being declared in entry CSS. DOM font declarations alone do not establish body text is DOM. B12/B20/B30/B35.
- **Confirmed:** text geometry carries `textWeights` and `lineWeights`. Active UI shaders reveal glyphs by falloff and atlas UV jumps/scramble, then settle to correct UVs; opacity, blink and technical block displacement are separate uniforms. Logo uses MSDF texture and replays a .25-second glitch reveal on hover, plus audio event. Scroll instruction reveal .4/.75 sec and hide .5 sec. B31/B32.
- **Confirmed:** input raycasts scene meshes through custom `Er=pA`; generates hover/touch/move/drag/click events, switches cursor for meshes and enables/disables per component. No need for DOM hit targets in this architecture. B38, 1062821.
- **Confirmed:** UI uses small if width<1600 **or** height<800; mobile if width<640 **or** height<640. Margins125/90 large,45/45 small,25/25 mobile; logo widths200/160/140. Camera aspect zoom and recomputed UI scene positions are explicit responsive mechanisms. This does not imply complete runtime parity between devices. B13/B20/B31.
- **Confirmed:** root audio defaults muted. Controller registers18 `.ogg` clips: looping music-highq,room,wind,igloo,shard,circles(portals),particles, plus beeps/beeps2/beeps3,click-project,enter-project,leave-project,project-text,logo,ui-long,ui-short,manifesto. Scene progress/hover/pointer velocity update volumes; click/detail transitions trigger clip events. Audio decode is moved to dedicated `audioworker-036a09db.js`, then channel data becomes WebAudio buffer. B14/B33.
- **Confirmed:** project detail has its **own custom text scroll**: wheel delta×1 in pixel-like UI units, arrow±150, touch−delta.y. `scrollTargetY` clamps0→scrollMax, actual scrollY smooths with FPS lerp.1 and translates the WebGL group. Content width min(viewport−40,500); font size18 at small threshold,24 large; scrollMax from measured MSDF content heights,25px gaps and260px reserved vertical margins. It fades near screen edges in shader. Links are raycast meshes calling `window.open(url,"_blank").focus()`, with .1-second reveal stagger and hover scramble/audio. B44 offset1446254, B45 offset1444616. Main scene scroll is disabled during detail while text scroll remains active.
- **Confirmed:** wheel normalization uses browser deltaX/deltaY directly; Firefox line deltaMode1 multiplies by33. Capture timing matters because target clamp can discard excess motion from very large individual wheel events. B46 offset1014823.

## Assets and performance assertions safe to cite

- **Confirmed:** geometry loader selects .drc/.bin decoding, caches promises, uses Draco decoder in worker; WASM wrapper/decoder fetched if WebAssembly is available, JS fallback otherwise. Asset base `/assets/geometries/`; decoder `/assets/libs/draco/`. B34 plus source around885571–900200.
- **Confirmed:** texture system caches by filename/load mode, routes KTX2→Basis-capable loader, distinguishes Data3D/LUT textures, explicitly handles sRGB/data/no-mipmap/nearest/repeat modes. KTX2/Basis transcoder, bitmap and EXR workers are each limited to1. Main loader points to `/assets/images/`, transcoder `/assets/libs/basis/`. `le.loadProgressive` exists but has **no call sites found**: do not claim active progressive texture upgrading. B36, 959817.
- **Confirmed:** MSDF worker `msdfworker-ac346fa7.js`, bitmapworker-046527f8.js, exrworker-41cbee65.js and audioworker-036a09db.js. Loader caches and typed-array transfer reduce repeated decode/main thread work; quantify bandwidth and actual worker activity from network/runtime captures separately.
- **Confirmed:** adaptive DPR observes FPS after2-second warm-up, pools samples over ≥4 seconds and5 samples, decreases multiplier by.1 below30FPS, increases by.1 at≥60FPS, floor.6 ceiling1. It stops after4 direction reversals. This is a performance control, not proof a given device sustained target FPS. B09, 1018870.
- **Confirmed:** only currently visible scroll composers render; when detail progress reaches1, background composers are skipped. Numerous meshes turn invisible outside animation windows; static matrices often disable auto update; batching/instancing/GPU computation occur in actual app paths. Bloom downsample/mipmap levels6, shared texture caches, compileAsync warm-up are all explicit.
- **Unknown:** precise runtime frame timing, memory occupancy, live draw/triangle counts, texture compression formats selected by GPU, complete WebGL extension list and individual framebuffer attachments. No source-only assertion should substitute for capture.

## Supplemental source/runtime reconciliation

- **Confirmed:** Hero Spector capture is an **intro-phase frame**, not a fully settled hero. `spector-hero-draws.json` command241 uses program2 with `uIntro=1` and p3's `tScene/uColor` shader; sky program17 has `uProgress=.626517`. First home navigation starts p3, then awaits both the1-second fade and `hero.playInAnimation()` (which awaits a5-second GSAP delayed call). Only after that barrier does it assign f3 and enable scroll. The switch is time-driven, **not triggered by first scroll**. The richer f3 compositor is verified as program1 in cube command225, detail command84 (`uDetailProgress=1`) and footer command282. Source B22 at1481132–1481400 and B17 playInAnimation. A settled-hero capture after >5 seconds would use f3, even without user input.
- **Confirmed:** First successful body click, touch end or keydown resumes the WebAudio context; contextReady resolves and HU emits `webgl_audio_mute_toggle` if currently muted, automatically switching the app to unmuted. NF sound UI listens to this same toggle event and reads muted state in a microtask. Consequently cube click can change Sound:Off to Sound:On without pressing the sound control. The UI control provides later manual toggling. Runtime screenshot differences are compatible with source, not proof of an accidental second click. B48/B49/B50. Playback of a given click clip additionally depends on decode readiness and context running state; do not claim audible clip execution solely from the event.
- **Confirmed with runtime capture:** Main post order in all sampled frames is composite→UI→bloom→SMAA. Hero: composite program2 command241 into target32, UI programs9/10/11 commands254–272 into target32, luminance program83 command283, six downsample draws program84 command295–345 down to23×15, five upsample program85 command359–411, bloom combine program86 command426, SMAA programs87/88/89 commands437/450/463 with final default framebuffer. Cube, detail and footer show the same latter chain and sizes. Thus global bloom receives UI pixels as well as scene pixels. These frame-local numeric program/target IDs are capture evidence, not stable semantic IDs for future reloads.
